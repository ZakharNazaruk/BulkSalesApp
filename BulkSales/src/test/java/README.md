# Тесты для BulkSales

Комплексное покрытие тестами системы электронной коммерции BulkSales.

## 📋 Структура тестов

### 1. Конфигурация (`config/`)
- **TestConfig.java** - базовая тестовая конфигурация с моками для внешних зависимостей

### 2. Утилиты (`util/`)
- **TestDataBuilder.java** - builder для создания тестовых объектов (Product, Order, User, Cart, Discount)

### 3. Юнит-тесты (`service/impl/`)

#### ProductServiceImplTest (37 тестов)
Покрывает:
- ✅ Получение всех/активных/приоритетных продуктов
- ✅ CRUD операции
- ✅ Фильтрация по категории
- ✅ Переключение активности и приоритета
- ✅ Сохранение с оптимизацией изображений
- ✅ Уведомления при низком остатке
- ✅ Обработка ошибок

#### CartServiceImplTest (17 тестов)
Покрывает:
- ✅ Получение/создание корзины
- ✅ Добавление товаров (новых и существующих)
- ✅ Удаление товаров
- ✅ Автоматический пересчет totalPrice
- ✅ Обработка граничных случаев (нулевое количество, большие числа)
- ✅ Обработка ошибок

#### OrderServiceImplTest (21 тест)
Покрывает сложную бизнес-логику:
- ✅ Базовое оформление заказа без скидок
- ✅ VIP скидки для VIP пользователей
- ✅ Процентные скидки (PERCENT) на уровнях PRODUCT/CATEGORY/GLOBAL
- ✅ Пороговые скидки (THRESHOLD) при достижении минимального количества
- ✅ BXGY скидки (купи X, получи Y бесплатно)
- ✅ Обновление VIP статуса при достижении порога
- ✅ Обновление статуса заказа с уведомлениями
- ✅ Списание остатков со склада
- ✅ Очистка корзины после оформления
- ✅ Обработка ошибок (пустая корзина, недостаточный остаток, неверный статус)

### 4. Интеграционные тесты репозиториев (`repository/`)

#### ProductRepositoryIT (18 тестов)
Тесты с реальной H2 базой данных:
- ✅ findByActiveTrue()
- ✅ findByPriorityTrue()
- ✅ findByCategoryIgnoreCaseAndActiveTrue() (регистронезависимый поиск)
- ✅ Сохранение и обновление продуктов
- ✅ Удаление продуктов
- ✅ Управление количеством
- ✅ Комплексные фильтры

### 5. End-to-End интеграционные тесты (`integration/`)

#### OrderCheckoutScenarioIT (12 тестов)
Полные сценарии взаимодействия всех компонентов:
- ✅ Базовый сценарий: создание пользователя → добавление в корзину → оформление заказа
- ✅ Применение различных типов скидок в реальных условиях
- ✅ Получение VIP статуса при достижении порога
- ✅ Комбинированные сценарии (VIP + категорийные скидки)
- ✅ Обработка ошибок (недостаточный остаток, пустая корзина)
- ✅ Многоэтапные сценарии (несколько заказов от одного пользователя)

## 🚀 Запуск тестов

### Запуск всех тестов
```bash
./mvnw test
```

### Запуск конкретного тестового класса
```bash
./mvnw test -Dtest=ProductServiceImplTest
```

### Запуск конкретного теста
```bash
./mvnw test -Dtest=ProductServiceImplTest#getAllProducts_ShouldReturnAllProducts
```

### Запуск только юнит-тестов
```bash
./mvnw test -Dtest=*Test
```

### Запуск только интеграционных тестов
```bash
./mvnw test -Dtest=*IT
```

## 📝 Соглашения о тестах

### Структура тестов (Given-When-Then)
```java
@Test
void testName_ShouldDoSomething_WhenCondition() {
    // Given - подготовка данных
    
    // When - выполнение действия
    
    // Then - проверка результата
}
```

### Именование тестов
- Используется формат: `methodName_ShouldExpectedBehavior_WhenCondition`
- Используются `@DisplayName` аннотации для русскоязычных описаний

### Независимость тестов
- Каждый тест независим и может выполняться отдельно
- `@BeforeEach` используется для подготовки данных
- Интеграционные тесты очищают базу данных перед каждым тестом

## 🔍 Особенности реализации

### Мокирование NotificationServiceClient
Все тесты используют мок `NotificationServiceClient` через `TestConfig`, чтобы избежать реальных вызовов внешнего сервиса.

### Тестирование сложной логики скидок
OrderServiceImplTest включает детальное тестирование всех типов скидок:
- Процентные скидки на разных уровнях
- Пороговые скидки с минимальным количеством
- BXGY (Buy X Get Y) скидки с различными комбинациями
- Комбинированное применение нескольких скидок

### Интеграционные тесты с H2
Используется H2 база данных в режиме PostgreSQL для максимальной совместимости:
```properties
spring.datasource.url=jdbc:h2:mem:testdb;MODE=PostgreSQL;DATABASE_TO_LOWER=TRUE;DEFAULT_NULL_ORDERING=HIGH
```

## 🎯 Рекомендации по разработке

1. **Покрывайте новую функциональность тестами** - добавляйте тесты вместе с новым кодом
2. **Тестируйте граничные случаи** - не только happy path, но и ошибочные сценарии
3. **Используйте TestDataBuilder** - для единообразного создания тестовых данных
4. **Следуйте Given-When-Then** - для читаемости и понятности тестов
5. **Пишите значимые DisplayName** - чтобы легко понять, что тестируется
